Personal native calorie tracker

Log food before the moment passes.

A private, device-owned SwiftUI app for iPhone 17 that turns a sentence or photo into a validated calorie estimate, saves it immediately, then learns the meals you repeat.

Native only SwiftUI, SwiftData, camera, Photos
Vertex first Private Gemini inference with an Apple offline fallback

Default interaction

Type or snap. A pulsing edge shows analysis in place; a valid result saves and returns to Today.

The core loop

Four steps. No ceremony.

Heavy onboarding, health scores, streak pressure, water tracking, and social mechanics stay out. The app opens to today and optimizes the one action that matters: capturing intake accurately enough to be useful.

01 Open Today See consumed, remaining, macros, and recent entries.
02 Log Describe it, take a photo, or choose one.
03 Analyze Known facts locally, Vertex for inference, Apple when offline.
04 Save Validated nutrition lands on Today automatically.

Fast by default

The floating Log action is reachable one-handed. Text and image have equal priority, and a repeat meal can be logged without another model call.

Honest estimates

Invisible oil, sauces, mixed dishes, and unclear portions remain stored as uncertainty metadata instead of pretending precision.

Local history

Confirmed entries, goals, thumbnails, and personal foods live on the phone. The gateway analyzes transient inputs but stores no meal history.

Use system glass for navigation, floating actions, camera controls, and sheets. Nutrition content stays on quiet, legible tonal surfaces so the hierarchy survives bright light, dark mode, Reduce Transparency, and one-handed use.

System shape

Device-owned data. Vertex-first inference.

The iPhone owns the product and all confirmed data. Exact nutrition and readable labels stay local; new meal descriptions and ordinary photos use the private Vertex gateway first, with Apple Intelligence as the offline fallback.

iPhone 17 · product and data owner

SwiftUI + protected local store

SwiftData, personal food memory, Foundation Models guided generation, Vision OCR, camera, PhotosPicker, protected files, and the direct-save experience.

→
Primary inference · authenticated HTTPS

Cloud Run gateway

Receives transient typed or sanitized-photo inputs. Handles a per-install bearer digest, upload limits, schema validation, idempotency, hard timeouts, and content-free logs.

→
Primary model · dedicated service identity

Vertex Gemini

A configurable pinned Flash-class multimodal model for complex photos and unknown foods, with low temperature, JSON schema, prompt versioning, and no durable image storage.

Route 0 · no model

Match a saved personal food or repeated meal and recompute from confirmed nutrition. This is the fastest and most dependable route.

Route 1 · Vertex

Use the private Gemini gateway for new typed meals and ordinary food photos. Every estimate returns the same schema, passes deterministic validation, and then saves.

Route 2 · offline

When the gateway is unavailable, use Foundation Models for typed extraction and availability-gated iOS 27 multimodal analysis. Vision label OCR remains local.

Credential boundary

The shared vertex-image-gen environment is operator-only and remains limited to reviewed static artwork. Its credential values are never copied into Swift, bundled resources, CI, Cloud Run variables, or source control. Runtime Vertex access uses a separate Cloud Run service account with least privilege and no downloaded key.

Private access

No account. One locked device.

Face ID with device-passcode fallback locks the app on launch and foreground. A one-time random device token is stored only in this iPhone’s Keychain; the gateway retains only its SHA-256 digest.

On device

Use LocalAuthentication for the app lock. The device token uses WhenUnlockedThisDeviceOnly, pending photos use complete file protection, and image metadata is stripped before upload.

At the gateway

Every request requires the paired bearer and an idempotency key. Only the configured digest is retained; bodies, model output, and authentication headers never enter logs.

In Google Cloud

No static service-account key, no Cloud Storage, and no meal database. Set a regional deployment, daily quota, budget alert, and max instances.

Shared intelligence contract

One validated shape, whichever model ran.

Vertex structured output and Apple’s offline fallback map into the same local draft. Models identify and structure; deterministic code validates item values and recomputes totals before automatic save.

Routing and analysis rules

  1. Check a confirmed personal-food match before calling any model.
  2. Prefer printed nutrition values when a label is readable.
  3. Use the private Vertex gateway for new meal inference.
  4. Separate visible facts from assumptions.
  5. Flag uncertainty around portion, oil, sauces, and hidden ingredients.
  6. Return item nutrition, not only a meal total.
  7. Use Apple Intelligence only when the gateway is unavailable.
  8. Never save or count an invalid response.

Local model

Four durable records.

SwiftData stores confirmed truth and resumable work. Images remain protected files, not large database blobs. Daily totals are always derived from confirmed meals so there is no second aggregate to drift.

Implementation order

Six shippable slices.

Each slice ends in something testable on the device. There is no long infrastructure detour before the native experience can be felt.

Slice 1

Native shell + local truth

Project, tokens, Today, lightweight goal sheet, SwiftData schema, confirmed entry lifecycle, and deterministic nutrition math.

Slice 2

Capture locally

One text-and-image composer, camera, PhotosPicker, protected source-input pipeline, pulsing analysis state, and validated direct save backed by fixtures.

Slice 3

Offline intelligence

Foundation Models typed extraction, guided Swift structures, availability handling, personal-food matching, Vision label OCR, and offline automatic save.

Slice 4

Private Vertex primary

Dedicated runtime identity, Face ID app lock, one-device Keychain pairing, digest authorization, shared schemas, quotas, idempotency, and contract tests.

Slice 5

Hybrid photo intelligence

Vertex meal-photo inference, local label tools, availability-gated iOS 27 offline fallback, assumptions, background upload, and correction reuse.

Slice 6

Personal release

Private eval meals, failure recovery, privacy/export/delete, accessibility, exact-device QA, signed install, and one week of real-use fixes.

Release rule

No AI-only “done.”

The release is ready only when typed, photo, offline, correction, and deletion flows work on the physical iPhone 17—not merely in previews or with mocked responses.

Failure design

Useful even when AI is not.

Network and model failures become explicit local states, not lost meals. Only validated entries affect the day.

Offline or interrupted

Use personal foods and on-device text intelligence without a network. Persist any fallback draft and file before upload, then resume safely on next launch.

  • Honor server retry guidance
  • Refresh auth once, never loop
  • Preserve text and image, then offer retry

Apple Intelligence unavailable

Check the system model before prompting and explain the exact state: Apple Intelligence is off, the model is still downloading, or the device is ineligible.

  • Never lose the captured inputs
  • Use Vertex when online and authorized
  • Retry locally when the model becomes ready

Ambiguous meal

Retain the uncertain part. Hidden ingredients and portion size get an uncertainty reason alongside the saved source input.

  • No false precision
  • Never save an invalid response
  • Keep uncertainty metadata with the entry

Malformed response

The gateway validates a strict schema, rejects non-finite, negative, missing, or implausibly large values, recomputes totals, and retries the model only once.

  • Version every client contract
  • Return typed errors
  • Keep payloads out of diagnostics

Cost or abuse spike

Resize before upload, select a low-latency Flash-class model through evaluation, cap request size and rate, and stop runaway spend at the project level.

  • Daily Vertex quota and budget alert
  • Cloud Run max instances
  • Repeat meals avoid another AI call

Definition of done

The personal release bar.

  • Runs as a native signed build on the user’s physical iPhone 17.
  • First launch uses Face ID or the device passcode, then opens Today without account onboarding; gateway pairing lives in Settings.
  • A typed meal uses the private gateway when configured, falls back on-device when needed, validates, saves, and returns directly to Today.
  • A saved repeat meal logs without a network or model call.
  • A new camera photo and a selected photo both save directly, alone or with written context.
  • Nutrition-label photos preserve printed serving math when readable.
  • Stored item-level nutrition deterministically rolls up to meal and day totals while only calories and three macros render.
  • Invalid and failed analyses never affect totals.
  • Offline drafts survive backgrounding, termination, and relaunch.
  • Duplicate retries create one analysis and at most one meal.
  • Unavailable providers preserve both inputs and offer retry; there is no manual-entry fallback.
  • Reopening an entry shows the exact written description and its protected sanitized source image.
  • No Vertex or service-account credential exists in the app bundle.
  • No raw meal text, image bytes, or auth tokens appear in logs.
  • Export and Delete all data work without a backend dependency.
  • Dynamic Type, dark mode, Reduce Motion, and Reduce Transparency remain usable.
  • A private evaluation set covers typed meals, drinks, mixed dishes, labels, low light, and multi-item plates.

Implementation notes

Current platform guidance.

These are reference links, not runtime dependencies. The plan itself remains one offline-capable HTML file with all styling inline.

Apple platform references

Foundation Models, guided generation, model availability reasons, and multimodal image prompting. Image attachments are currently an iOS 27 beta API, so the implementation availability-gates them and preserves the iOS 26 fallback. UI and storage references: Adopting Liquid Glass, GlassEffectContainer, AVCam camera sample, and SwiftData ModelContainer.

Google Cloud references

Google Gen AI SDK on Vertex AI, Vertex AI Node and ADC quickstart, Cloud Run authentication, and structured response configuration.

Build-time credential handling

Authorized local Geo Repair credentials may be read only by operator-run image generation or the private local gateway process. Never print, copy, commit, bundle, or send them to the app. Production Vertex remains ADC-backed through a dedicated Cloud Run runtime identity.
